# Image and card policy

## Storage decision

Images must be stored as files, not inside the database.

The database stores metadata and URLs/paths only:

- `url`
- `storagePath`
- `altText`
- `mimeType`
- `width`
- `height`
- `sizeBytes`
- `createdBy`

## Why not store images in DB

Storing binary images in MySQL increases database size, makes backups heavier, complicates cache/CDN behavior and can hurt performance. Use file storage and keep URLs in DB.

## MVP storage options

Primary MVP option:

- Hostinger filesystem upload directory, e.g. `/uploads`.
- Store relative/public URLs in MySQL.
- Optimize before/after upload.

Future options if needed:

- Cloudinary free/paid
- S3-compatible storage
- R2
- External image URLs for opponent logos

## Image types

- Team logo
- Team banner
- Opponent logo optional
- Player photo
- First-team premium card image
- Generated standard card assets
- News cover image
- Hero/banner images

## Opponent logos

Opponent logo is optional. If used, it should be stored as an uploaded image or external URL with cached metadata. If absent, use a generic placeholder.

## Cards

### First team

First-team player cards are uploaded premium images managed by `superadmin` or `manager`.

### Other teams

Other team player cards are generated by the web using:

- foot
- public name
- shirt number
- country flag
- position
- goals
- assists

## Upload permissions

Only `superadmin` and `manager` can upload images.

Coaches cannot upload player photos, logos, cards or news media.

## Optimization rules

- Prefer WebP/AVIF where possible.
- Do not upload huge unoptimized files.
- Keep alt text.
- Generate thumbnails where useful.
- Avoid storing video files.
